Enhancing Linux Endpoint Security with Wazuh

Unauthorized process detection on Linux endpoints — custom Wazuh rules, real-time alerts, and a simulated Netcat attack.

Project Overview

At 10ALYTICS‑DC, a growing data center and cloud services provider, threat intelligence showed increased attempts to exploit Linux endpoints using unauthorized tools such as Netcat. Netcat is a legitimate utility, but attackers weaponize it for data exfiltration, reverse shells, and unauthorized remote access. A routine audit found engineers and contractors occasionally using Netcat without authorization. This project uses Wazuh, an open-source SIEM and XDR platform, to detect unauthorized Netcat executions in real time.

View project files on GitHub: https://github.com/imhardeyboi/imhardeyboi.github.io/tree/main/projects/wazuh-soc-detection

  • Wazuh command monitoring on Linux endpoints
  • Custom detection rules for Netcat
  • Real-time alerts in the Wazuh dashboard
  • Simulated attack from Kali Linux

Lab Environment

A VirtualBox-based lab simulating a realistic enterprise environment, with all three machines on the same network.

Communication flow: the endpoint executes a command, the Wazuh agent collects the process logs, the logs are forwarded to the manager, custom rules detect Netcat usage, and alerts are generated in real time.

Configuration and Implementation

  • Wazuh Manager: a custom rule in /var/ossec/etc/rules/local_rules.xml triggers every time a Netcat program is launched.
  • Ubuntu endpoint: the Wazuh agent was installed from the terminal, and ossec.conf was edited to enable process and command monitoring.
  • Kali Linux: SSH was enabled for remote access to the Ubuntu endpoint during the attack simulation. Connectivity between all three machines was verified with ping and ifconfig checks.

Attack Simulation

Kali Linux acted as the attacker, running Netcat against the Ubuntu endpoint — Netcat listening for incoming connections with nc -lvp 4444, mimicking a reverse shell setup.

Detection Results

Wazuh detected the activity and generated an alert in the dashboard:

  • Alert: netcat listening for incoming connections — a Netcat process in listening mode on port 4444.
  • Severity: level 7 (medium-to-high), indicating suspicious activity requiring investigation.
  • Evidence: Wazuh Discover showed multiple log entries of Netcat actively listening on port 4444 at different timestamps, with a matching spike in the histogram.

    Recommendations

    • Prevent: application controls / process whitelisting, harden endpoints by disabling unnecessary services, closing unused ports, and enforcing firewall rules.
    • Identity and access: least privilege and multi-factor authentication.
    • Detect: network-level monitoring for unusual traffic, reverse shells, and tunneling.
    • Respond: Wazuh active response for automated containment, such as blocking malicious IPs or stopping suspicious processes.
    • Maintain: disciplined patch management and regular security audits.

    Real-World Relevance

    Attackers abuse everyday tools like Netcat to build backdoors and move data quietly. This project shows how a SOC detects that abuse early — before a reverse shell becomes a breach — using process monitoring, custom rules, and real-time alerting. It demonstrates the practical detection engineering skills expected from SOC Analysts.
